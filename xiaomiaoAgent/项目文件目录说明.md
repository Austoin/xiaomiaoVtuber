# xiaomiaoAgent 项目文件与目录说明

## 1. 项目定位

`xiaomiaoAgent` 是 Python 3.11+ Agent 核心和 React WebUI。后端包名为 `nanobot`，提供模型 Provider、消息总线、渠道接入、工具系统、会话记忆、定时任务、HTTP API 和 CLI；`webui` 提供管理与对话界面。

本文按“根文件逐项、一级目录逐项、核心源码按模块和文件职责、第三方/缓存/构建目录按类别”的口径覆盖项目。`.venv`、缓存、前端依赖和 vendor 内部的海量第三方文件不逐文件复述。

## 2. 运行链路

```text
渠道/CLI/WebUI
      │
      ├─ nanobot/api（OpenAI 兼容 HTTP、xiaomiao 事件）
      ├─ nanobot/bus（消息类型与队列）
      └─ nanobot/agent（上下文、模型、工具、记忆、子 Agent）
                      │
                      ├─ providers（Anthropic/OpenAI 等）
                      ├─ tools（文件、Shell、Web、MCP、媒体）
                      └─ session / cron / heartbeat
```

## 4. 一级目录

### `docs/development`

`design.md` 记录设计目标，`gotchas.md` 记录已知陷阱，`security.md` 记录安全约束。它们是开发 Agent 的上下文，不是运行时代码；运行时角色、技能和记忆仍位于 `nanobot/templates`、`nanobot/skills` 与 Agent workspace。

### 缓存、环境和构建目录

- `F:\xiaomiaoVirtual\.cache\agent\nanobot`：运行时配置、会话、媒体、历史和 workspace；由根目录 `cache_config.py` 统一管理。
- `F:\xiaomiaoVirtual\.cache\pytest`：pytest 可复用缓存；一次性 `tmp_path` 通过 `--basetemp=../../.cache/xiaomiao-agent-pytest` 放在主 Git 仓库外，避免 GitStore 将测试临时仓库误判为嵌套仓库。该 basetemp 是临时工作区，不应与可复用缓存混淆。
- `F:\xiaomiaoVirtual\.cache\ruff\xiaomiaoAgent`：Ruff 静态检查缓存，已通过 `pyproject.toml` 显式配置。
- `.venv`：本地 Python 虚拟环境，可由 `uv sync` 重建，不应提交。
- `dist`：Python 发布构建产物，可重建；本次已清理本地生成目录。
- `webui/node_modules`：前端依赖安装目录，可用 `npm ci` 重建，不是运行时缓存。
- `nanobot/web/dist`：WebUI 发布资源，已纳入 Python 打包配置，不能删除后提交。

缓存、环境和本地构建目录不应提交；`nanobot/web/dist` 是唯一需要保留并随 Python 包发布的构建资源。

### `nanobot`

后端核心包：

- `__init__.py`：包公开 API 和版本入口。
- `__main__.py`：`python -m nanobot` 的 CLI 入口。
- `nanobot.py`：面向 Python 调用者的高层 `Nanobot` facade 和单次运行结果模型。
- `agent`：Agent 主循环、上下文、运行器、记忆、技能、子 Agent、自动压缩和 hooks。
- `agent/tools`：Agent 可调用工具，包括文件系统、搜索、Shell、Web、MCP、cron、消息、notebook、spawn、图像生成、MarkItDown、Scrapling、自检、舞台和 xiaomiaobot 服务桥接。
- `api`：OpenAI 兼容 API，以及 xiaomiao 事件、配置和健康端点。
- `bus`：入站/出站消息数据结构与异步队列。
- `channels`：DingTalk、Discord、Email、Feishu、Matrix、Mochat、MSTeams、QQ、Slack、Telegram、WebSocket、WeCom、Weixin、WhatsApp 等渠道适配。
- `cli`：Typer 命令、onboard、模型辅助和流式终端。
- `command`：内置 `/dream` 等命令、命令路由和参数解析。
- `config`：配置 schema、loader、路径、统一根目录和校验。
- `cron`：定时任务持久化、调度与执行。
- `heartbeat`：周期性心跳和后台唤醒。
- `providers`：Anthropic、Azure、Bedrock、GitHub Copilot、OpenAI Codex、OpenAI-compatible，以及图像、转录 Provider。
- `security`：网络访问策略等安全控制，重点文件为 `network.py`。
- `session`：会话管理、历史和上下文生命周期。
- `skills`：ClawHub、cron、GitHub、图像生成、memory、my、skill-creator、summarize、tmux、update-setup、weather 等内置技能。
- `templates`：AGENTS、SOUL、USER、TOOLS、HEARTBEAT、memory 和 Agent prompt 模板。
- `utils`：artifacts、document、evaluator、gitstore、media、prompt、restart、runtime 等跨模块工具。
- `web`：打包后的 WebUI 静态资源，通常由前端构建复制到这里。

记忆相关文件集中在 `nanobot/agent/memory.py` 及 workspace：默认 workspace 为 `F:\xiaomiaoVirtual\.cache\agent\nanobot\workspace`，内含 `memory/MEMORY.md`、`history.jsonl`、`.cursor`、`SOUL.md` 和 `USER.md`。这些文件可能包含用户内容，不应提交。

### `tests`

pytest 测试树按目录覆盖：

- `agent`：主循环、上下文、记忆、hook、自动压缩和子 Agent。
- `channels`：各聊天渠道的消息转换和生命周期。
- `cli`、`command`：命令行和聊天命令路由。
- `config`：schema、加载、环境变量和路径。
- `cron`、`heartbeat`：调度、持久化和后台唤醒。
- `providers`：模型、图像和转录 Provider。
- `security`：网络安全和访问限制。
- `session`：会话历史和上下文管理。
- `tools`：文件、Shell、Web、MCP、媒体和其他工具。
- `utils`：文档、媒体、runtime 等辅助模块。
- 根级测试文件：API、消息总线和跨模块集成覆盖。

运行全量测试前检查外部服务凭据；网络或第三方渠道测试应使用 mock。

### `vendor`

- `markitdown`：内置文档转换源码。
- `scrapling`：内置网页抓取源码。

这是供应商代码，升级或修改必须同步许可证、`THIRD_PARTY_NOTICES.md` 和安全审查；不要把它们与本项目业务包混为一谈。

### `webui`

React + TypeScript + Vite + Tailwind + shadcn/ui 前端：

- `src/components`：页面和可复用组件。
- `src/hooks`：数据请求、状态和生命周期 hook。
- `src/i18n`：多语言资源和切换。
- `src/lib`：API 客户端、工具和类型辅助。
- `src/providers`：主题、查询、路由等上下文 Provider。
- `src/tests`：前端测试。
- `src/workers`：后台 Worker。
- `package.json`、`vite.config.*`、`tsconfig.*`：前端依赖与构建配置。
- 当前没有独立 `images/` 或 `public/` 图片目录；图片处理主要由 `src/lib/media.ts` 和 `src/workers/imageEncode.worker.ts` 完成。

构建结果输出到 `nanobot/web/dist`，开发服务器默认使用 5174；Agent Gateway 默认端口为 8765。

### `xiaomiao_agent`

品牌化入口包，仅包含 `__init__.py` 和 `__main__.py`，用于以 `python -m xiaomiao_agent` 方式启动或暴露版本信息。业务实现仍在 `nanobot`。

## 5. 常用操作

```powershell
uv sync
uv run pytest
uv run ruff check .
uv run python -m nanobot
uv run python -m xiaomiao_agent
cd webui; npm ci; npm run dev
```

部署前应分别验证 Python 单测、类型/静态检查、WebUI 构建和 API 健康检查。

## 6. 扩展与维护建议

1. 新渠道实现 `channels` 的统一接口，消息转换放在适配层，避免污染 Agent 核心。
2. 新 Provider 复用统一 streaming/event 模型，并补充重试、超时和错误映射测试。
3. 新工具拆成短函数，声明权限、输入 schema、超时和副作用；高风险操作必须显式拒绝。
4. 配置变更先更新 schema、默认模板、文档和迁移逻辑。
5. 前后端 API 变更同步更新 OpenAPI/类型、WebUI 客户端和集成测试。

- 本目录中的 `.venv`、`node_modules`、`nanobot/web/dist` 和运行时模型/媒体不属于可删除源码；清理时只处理 `__pycache__`、`.pytest_cache` 等生成目录。

## 8. 安全注意

- 不要提交 API key、Cookie、渠道 token、用户记忆、`.venv` 或构建产物。
- 网络工具必须经过 `security/network.py` 的 SSRF、协议和域名策略。
- vendor 代码和第三方许可证不可删除。
- 日志中避免记录完整请求头、授权信息和用户私密内容。
